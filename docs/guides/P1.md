# P1: Workload, quantized BP, baselines

**Branch:** `p1-workload-bp`

## 1. Role

You produce the ground truth everything else stands on. That means the Stim circuits, the sampled
shots and decoding graphs, and our own quantized normalized min-sum BP, plus the reference decoders
(ldpc BP+OSD with measured CPU latency, and PyMatching for the surface code). Your functional traces
decide the logical error rate (LER) claim: quantized BP must not be worse than float BP. You are the
most upstream person, so **getting files out early matters more than getting them perfect**.

**You own:** `src/qdec/workload/` (`circuits.py`, `graphs.py`, `bp_minsum.py`, `baselines.py`,
`functional.py`), `scripts/p1_make_data.py`, `scripts/p1_run_functional.py`, `tests/p1_*`.

## 2. Inputs and outputs

**Inputs:** none from teammates. You read `contracts.QUICK_GRID` / `FULL_GRID`, `SEED_TRAIN`,
`SEED_TEST`.

**Outputs** (always written through `qdec.io`):

| File | Format | Read by |
|------|--------|---------|
| `data/shots/<tag>.npz` for **both** SEED_TEST and SEED_TRAIN | `dets` bool[S×D], `obs` bool[S×O], `det_coords` float[D×k] | P2 cache |
| `data/graphs/<code>_d<d>_p<p>.npz` | `H` csr, `L` csr, `priors` float (via `io.save_npz`, which handles sparse) | P2 cache / cost model |
| `data/graphs/<code>_d<d>_p<p>.json` | `GRAPH_STATS_KEYS` | P2 cost model |
| `data/traces/functional_<tag>.parquet` | `FUNCTIONAL_COLS` | P2 cost model, P3 plots |
| per-shot BP+OSD wall-clock latency | agree the hand-off with P2 on Day 1 (e.g. an extra npz in `data/traces/`) | P2's `bposd_cpu` rows |

The `<p>` in graph names uses `f"{p:g}"`, like `Workload.tag`. `scripts/p1_make_data.py` already
loops over the grid in the right shape. `make functional MOCK=1` writes `mock_functional` traces,
so P2 can test their file loading before your real ones exist.

> Measured latency isn't in any schema yet. If P2 needs it as a column, raise a contract change
> (see [WORKFLOW.md](../WORKFLOW.md)). Don't add columns on your branch.

## 4. Pitfalls

- **Fixed seeds:** always use `w.seed`; TRAIN shots use `dataclasses.replace(w, seed=SEED_TRAIN)`. Never `np.random` without a seed.
- **Cache trains only on TRAIN:** you write both seeds. Don't mix them up in filenames (the tag contains the seed).
- **Tails, not means:** keep per-shot iteration counts and latency, never averages only. The tail is the whole story downstream.
- **Label hardware numbers MODELED:** your CPU latency is the one MEASURED number. Record CPU model and thread count.
- **Use QUICK_GRID while developing.** FULL_GRID only from Day 3 morning.
- Use `decompose_errors=False` for the BP graph; `bp_iters == max_iters` when BP did not converge.
