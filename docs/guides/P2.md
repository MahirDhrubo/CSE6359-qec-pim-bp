# P2: DecodeCache and the cost model

**Branch:** `p2-cache-cost`

## 1. Role

You build the two things that make this a systems paper. One is **DecodeCache**: split each shot's
detection events into clusters, give each cluster a translation-invariant key, store corrections
learned from TRAIN shots in a CAM, and serve a shot from the cache only when every cluster hits
and is isolated. The other is the **cost model**: per-operation latency and energy (all MODELED,
all cited) turned into a per-shot service time for each of the 7 `System` baselines, plus the
per-iteration prices P3's controller uses. You sit in the middle: P1 feeds you, and you feed P3.

**You own:** `src/qdec/cache/` (`splitter.py`, `keys.py`, `cam.py`), `src/qdec/costmodel/`
(`op_costs.yaml`, `conventional.py`, `pim.py`, `service.py`), `scripts/p2_build_cache.py`,
`scripts/p2_build_costs.py`, `tests/p2_*`.

**Day 4**

## 4. Pitfalls

- **Fixed seeds:** your Day-1 Stim shots also use `SEED_TRAIN` / `SEED_TEST`.
- **Cache trained only on TRAIN.** Evaluating on shots the cache was built from is the one mistake that invalidates the whole cache result. Add a test that fails if build sees a SEED_TEST tag.
- **Tails, not means:** a 70% hit rate means nothing if the misses are the slow shots. Report latency per path.
- **Every hardware number is MODELED and has a `source`.** No uncited constants in Python, so read everything from `op_costs.yaml`.
- **Use QUICK_GRID while developing.**
- A shot is a hit only if **all** clusters hit **and** pass isolation; `fail_cache` is null on a miss.
