# P3: Queue simulator, controller, results, slides

**Branch:** `p3-queue-results`

## 1. Role

You turn service times into the result that matters: **does the decoder keep up?** The discrete-
event queue simulator feeds one decode window per syndrome round into the decoder and tracks
waiting time, queue depth and whether the backlog stays bounded. The backlog-aware controller
(`System.FULL`) caps BP iterations when the queue grows. You also own every figure, the summary
tables, the slides and the demo. Your headline is that two systems with the same mean latency can
behave completely differently in the tail, and the tail is what causes backlog.

**You own:** `src/qdec/queue/` (`sim.py`, `controller.py`), `src/qdec/results/` (`plots.py`,
`tables.py`), `scripts/p3_make_results.py`, `scripts/p3_demo.py`, `tests/p3_*`, `slides/`.

## 2. Inputs and outputs

**Inputs:**

| File | Schema | Until it exists, use |
|------|--------|----------------------|
| `data/costs/service_<tag>.parquet` | `SERVICE_COLS` | `qdec.mocks.mock_service(tag)`, which covers all 7 systems with heavy tails |
| `data/costs/iter_costs.json` | `{tag: {system: {per_iter_ns, osd_ns, cache_ns}}}` | `make costs MOCK=1` writes a placeholder |
| `data/traces/functional_<tag>.parquet` | `FUNCTIONAL_COLS` (bp_iters, osd_ran, fail_*) | `mock_functional(tag)` |
| `data/traces/cache_<tag>.parquet` | `CACHE_COLS` | `mock_cache(tag)` |

**Outputs:** figures and tables in `results/` (committed on Day 4). `--mock` runs write
placeholders to `results/mock/`, which is git-ignored. Re-pricing under the controller uses the
contract formula:
`capped = min(bp_iters, budget) * per_iter_ns + (osd_ns if bp_iters > budget or osd_ran else 0)`.

## 4. Pitfalls

- **Fixed seeds** for synthetic latencies and any resampling.
- **Cache trained only on TRAIN:** if a hit rate looks too good, check that P2 evaluated on SEED_TEST tags.
- **Tails, not means.** Always show p99 / p99.9 and the CDF, and use a log x-axis for latency.
- **Label every hardware number MODELED** in figure titles or captions, and mark DPU/FPGA bars as "published".
- **Use QUICK_GRID while developing.**
- Shots must be fed **in shot_id order**; sort each `(tag, system)` group before simulating.
- Warm-up: drop the first few hundred windows from tail statistics, or state that you didn't.
